# 播放器能力与播放速度移植

本轮参考哔哩漫游的功能意图，以本工程现有 Modern API 101/102、KavaRef 成员解析、
FeatureInstaller、Moss 回调代理、配置白名单和设置布局重新实现，不引入新的生产依赖。
功能默认关闭／跟随宿主；修改后需重启哔哩哔哩主进程。

## 功能与边界

| 设置 | 行为 | 不做的事 |
| --- | --- | --- |
| 后台播放 | 调整已有播放响应中后台播放能力的客户端禁用／支持标志 | 不生成播放地址，不解锁付费视频，不绕过系统后台限制 |
| 小窗播放 | 调整小窗能力，并开放 MINIPLAYER 菜单的两个已验证构造槽位 | 不全局修改其他菜单或悬浮窗权限 |
| 投屏 | 调整投屏能力的客户端禁用／支持标志 | 不修改设备发现、DRM、服务端授权或画质 |
| 禁用长按加速 | 只消费 TripleSpeed 业务监听器的长按开始回调 | 不 Hook 全局触摸，不拦松手清理及其他手势 |
| 自定义长按倍速 | 修改加速协程构造器捕获的 Float 参数，范围 0.25～4 倍 | 不改最终字段、不轮询速度；禁用加速时不安装此路径 |
| 默认播放倍速 | 在速度管理器构造完成后初始化基础 Flow | 不写临时 Flow，不持续覆盖用户手动选择，不承诺每次切视频都重新覆盖 |

GUI 位置为「增强 → 增强进阶设置 → 视频播放页」，分为「播放器能力」「播放速度」两个小组。
自定义倍速最多两位小数，另提供「跟随哔哩哔哩」。禁用长按时保留自定义值，并在摘要中明确
提示暂不生效。英文、简体、繁体资源同步；既有分类 marker 顺序与水平留白不变。

## 安装与热路径

- PlayerCapabilityFeatureInstaller 覆盖 playerunite / playurl 两族同步和异步响应，复用
  MossResponseHandlerProxy，原响应身份和错误／完成回调保持不变。
- PlayerCapabilityAccess 在安装期解析成员，按 newBuilder(original) 的真实返回类型定位
  builder，不写死混淆的内部类名。复制选中的 ArcConf 和容器，全部副本准备完成后才写顶层
  配置字段；默认回复、没有视频信息的回复放行，未选字段、未知字段和视频数据保留。
- 共享协议只写 2（投屏）、9（后台）、23（小窗）中已选项，不包含 36（听视频）。
  已开放的能力不复制，第二次经过响应边界是幂等的。
- PlayerSpeedLocator 在安装期核验稳定业务类、构造参数及字段类型；混淆的外部服务 owner
  和双 Flow 字段名不作为候选常量。8.x 有基础／合成两个 getter，9.x 内联后只有一个；
  只接受已验证的一至两个 Float getter，初始化前后整组读回。
- 仅在“两个 Flow 中唯一一个为 Float 1、另一个为 null，速度 getter 均为 1”的初始状态写入。
  写后 Flow 和 getter 必须全部回读为目标值，否则尽力恢复基础值，不上报 APPLIED。
- 默认配置不注册 Hook；回调不执行类扫描、文件 I/O、IPC、定时轮询或持久化，不缓存播放器、
  View、请求或响应实例。额外分配按响应／管理器／长按事件发生，不在逐帧更新中发生。
- 安装覆盖分母包含已启用但解析或注册失败的单位，缺失不会被隐藏成全覆盖。诊断中心增加
  player_capabilities 和 player_speed。ADAPTED、OBSERVED 和 APPLIED 含义保持分离；
  仅修改小窗构造参数不冒充已验证的模型改写。

## 配置兼容

六项新增配置进入 SettingsCatalog v13（119 项，118 项可自动恢复）；两个倍速用百分比整数
存储，0 为跟随宿主，不新增 Float 协议类型。Remote schema 仍为 4；发布全量新目录后宿主才
接受授权配置。旧备份中不存在的新项保留当前值，不将缺失视为 false 或 0。

升级模块后应先打开模块设置页，确认配置发布完成，再重启哔哩哔哩。旧目录与新宿主 Hook
不匹配时仍按既有授权协议全部拒绝，不增加私有文件或广播回退。
