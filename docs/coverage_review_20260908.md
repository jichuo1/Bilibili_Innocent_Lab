# 同类覆盖问题审查（2026-09-08）

## 范围与证据边界

对 41 个 FeatureInstaller 源文件进行了入口、提前返回、响应模式和状态计算的静态检索，
重点追踪推荐、评论、搜索、动态、Story、弹幕及播放器链路。已有真实消费点的 getter 不因
“看起来只有 getter”就改成全局网络 Hook。结构存在、注册成功、实际过滤和真机页面结果分别记录。
本报告不是所有设备/全部页面均已验收的声明；没有安装设备、主动打开宿主或改动云端。

## 本轮修复

| 功能 | 确认的问题 | 处理 |
| --- | --- | --- |
| 搜索默认词 | 仅同步响应；逐字段就地改写；少数字段解析成功也能被视为完整 | 同步/异步共用副本清理器，全部成功才交付；保持路由字段；缺字段或模式报 partial |
| 动态净化 | 列表读取依赖先失败会跳过话题/UP 栏；共享注册数可能冒充子载体覆盖 | 列表载体单独可空，保留话题/UP 路径；按实际适用 feed 的成功注册数报告 |
| 评论过滤 | 正文和等级链在定位/安装阶段是全局硬依赖，阻断独立判据 | 正文/等级/作者/@ 依赖分别校验；用户名和 UID 规则仅启用可读部分；保留缺失分母 |
| 搜索结果 | 标题、用户名、UID 被绑为一个必需组；两个广告字段必须同时在 | 各字段独立可用；保留可执行过滤，对未覆盖的已选条件报 partial |
| Story | 某一个已选类型读不到时，整个过滤不装 | 只降级该类型，其余类型继续工作；不猜测未知数据类型 |
| 首页推荐 | 返回结果 complete=false，但状态文本仍可 success | 文本和结构化完整性保持一致，不改过滤规则 |
| Banner | 叶子是 partial，父结果和状态却仍完整成功 | 复用相同完整性判定，不改收起边界 |

- 相关推荐已有返回列表、DTO/内部写回及受限渲染层组合，不替换为更宽泛的清空策略。
- 评论净化、分享、直播、系统媒体通知等沿用各自已验证的成员/业务入口，不借本轮扩大作用域。
- 支付/站外链接、播放器视频地址、章节点、普通弹幕、权限与配置授权不变。
- 首页影视过滤仍是独立待实施方案，不在此次同类缺陷修复中新增设置。
