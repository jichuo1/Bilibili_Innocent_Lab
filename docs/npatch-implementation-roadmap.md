## 2026-10-26 免 Root 专项复查

本轮按用户要求分批安排七个子代理审查配置/恢复、宿主载体、操作体验、重启、诊断及独立差异复核。范围限定为免 Root 特有问题及免 Root 操作便利性；不恢复通用业务矩阵，也不改变 `EmbeddedModePolicy.SUPPORTED=false` 的集成模式暂停政策。

本轮独立交付单元：

- NPatch 快照复用标准发布的偏好归一化，旧类型值不再令整份配置构造失败；仅在快照中回落，不改原偏好或纳入凭据。
- NPatch 快照按固定字符预算容纳 UTF-8 中文规则，保留旧最坏字符载荷、单字段及直达文档限制，并用独立 Android 进程验证 Binder 传输。
- LSPatch 识别 `assets/lspatch/origin.apk`，与 NPatch 共用已验证的原包来源和 native 可读视图；无 DEX 的资源 split 继续跳过，混合/缺损载体拒绝。
- LSPatch 激活卡不再借用另一管理器服务的框架名/API；只有匹配的在线 LSPatch 服务补充 API 版本。
- NPatch 支持诊断保留暂未响应子进程的有界启动历史；历史只写回磁盘，不充作本次运行证据，安装身份变化后隔离旧历史。
- LSPatch 接入现有配置值热应用白名单，以 publication generation 校验更新；仍要求当前授权、构建内容一致、主进程完整安装证据及期限，结构变更继续要求重启。
- LSPatch 显示专属向导和自动直达说明，隐藏无效的 NPatch 开关；向导增加对应管理器及模块系统详情入口，不自动修改后台策略。
- 已安装但未运行的 Shizuku 可进入恢复面板并打开管理器；仍无重启能力，Root → Shizuku → 手动优先级不变。

验证记录位于本地忽略目录 `captures/noroot-comprehensive-20261026/`。当前实机基线为一加 `13a7a291`、Android 16、B 站 9.13.0、LSPatch 1.2（487）Manager 模式。NPatch 存储与协议问题使用隔离 Android 夹具；本轮不将这些结果外推为重新切换 NPatch 载体、集成模式、Root 设备或账号内完整业务验收。LSPatch 全套进程支持包和其它未实测框架仍不冒充已补齐。

- Debug / AndroidTest APK 构建成功；JVM 共 4400 项，0 失败、0 错误、1 项既有跳过。快速 Lint 通过，261 条警告，原有 3 项错误 baseline 未扩展。日志为 `gates-pass.log`，测试汇总为 `unit-tests.json`；后续仅调整 AndroidTest 夹具，最终构建与快速 Lint 记录为 `test-binder-flags-gates.log`，适用的生产分析结果复用缓存。

2026-10-21 用户明确要求正式支持 embed，并推进完整增强。embed 作为与 Manager 并列的支持模式，后续覆盖现有模块功能、实际宿主使用流程及完整安装/升级/恢复/诊断链路。原 F10 的“最小闭环”只代表基础设施阶段，不再作为 embed 的最终交付目标。

原阶段 2 更名为 **2A 基础闭环**，已提交为 `ed529619`；其 `:web` 整进程临时隔离已由 2B.1 的原生 TLS/linker 锁修复替换，恢复原 Hook 注册时序。**2B 正式准入已于 2026-10-22 完成**，范围限定为 B 站 8.90.2、固定修复版 833、签名等级 2、Android 16/arm64 的 Manager/embed；最终证据见文末及[支持说明](npatch-release-support.md)。已移除相关实验性文案，其它组合继续标为未验证。**阶段 3 已完成参数矩阵、实际 native 诊断与后台缓存复用，阶段 4 已完成有界支持证据与本地 ZIP 导出**，覆盖两种模式，详见文末；阶段 5 已完成主进程按需适配、子进程准备优化、时序评估及双模式最终验收，embed 实际收益未达原 20% 期望；阶段 6 的 F11、N3、F12、F14 已全部完成，详见[阶段 6 记录](npatch-stage6-experience.md)。

### 2026-10-21 阶段 2B.1：Web 原生死锁修复

本节更新当前状态，上述 2A 的 `GATED` 表格只保留为历史对照。用户要求先完成无需账号的部分；登录、下载及账号授权流程仍为待验，不作为本轮阻塞，也不记为通过。
