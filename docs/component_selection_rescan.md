# 宿主版本变化后的扫描勾选归并

适用范围：自定义「我的」页、底栏、首页标签、首页组件。四个面均走同一查询与保存链路。

用户主动重新读取时，只有通过 nonce、摘要、请求面、主进程、宿主版本/安装时间和模块版本
校验的非空扫描结果才进入保存。若该面上一次扫描的宿主 versionCode 与本次不同，
将该面的勾选 selector 与本次扫描键集合取交集；升级和降级使用同一规则。
已隐藏（showing=false）或本次不可编辑但标识仍存在的项继续保留。按宿主实际使用的
selector 匹配，不因展示标题变化删除稳定 ID，也不猜测不同混淆类名对应同一组件。

只更新该面的 `*_hidden_selectors`，手填 `*_hidden_rules` 和历史手填 ID 不变。
来源与选择使用同一个 SharedPreferences Editor 保存，并由已有设置监听器发布新配置。
当前宿主进程仍持有启动时的配置快照；清理后重启宿主使配置生效。

模块侧和宿主缓存侧的来源版本均按面隔离。模块侧旧的全局来源只作为尚未迁移面的历史
比较基线，新的扫描不再覆盖它；宿主侧旧全局缓存不能证明具体面的来源，需重新访问
对应宿主页采集后才可提供扫描结果。

同版本重新读取不自动删项；超时、未访问页面、无效响应、空列表和缓存回退也不清理。
现有协议无法区分「完整扫描确实为零项」与「尚未采集到」，所以空列表维持无效结果。
没有任何来源记录的旧配置先建立基线，不能据此推断版本已变化。扫描列表是运行期已
观察到的候选集合，用户在版本变化后主动读取时，未观察到的旧勾选按本需求释放。

回归测试 `ComponentSelectionReconciliationTest` 通过真实 Store 的键写入路径检查
四面升级/降级、保留有效隐藏项、手填不变、旧来源迁移和无效结果不推进版本。
