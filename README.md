## 项目简介

Bilibili Innocent Lab，是一个面向 Android 哔哩哔哩客户端的 Xposed/LSPosed 模块。项目的主要目标，是在尽量保持客户端原有视觉结构和操作习惯的前提下，对部分影响使用体验的界面内容进行净化，同时补全评论、视频简介、第三方扩展兼容和版本适配等方面的交互能力。

本模块并不是一个独立的哔哩哔哩客户端，也不会替代官方应用。它以运行时 Hook 的方式加载到目标应用进程中，对特定界面、数据绑定和交互入口进行有限修改。用户仍然使用原有的哔哩哔哩账号、播放器、推荐系统、评论区和视频详情页，只是在模块启用后，可以根据自己的需要开启或关闭相应功能。

项目强调“可选择、低侵入、可恢复”。绝大多数功能都提供独立开关，用户可以只启用自己需要的部分；模块不会要求所有功能必须同时开启。对于实验性功能，设置界面会给出明确提示，便于用户根据当前客户端版本和设备环境自行决定是否使用。

由于哔哩哔哩客户端会持续更新，内部类名、方法签名、布局结构和数据模型也可能发生变化，本项目加入了运行时版本适配、适配结果缓存和手动重新适配机制，尽可能降低客户端升级后功能整体失效的概率。但任何基于 Hook 的模块都无法保证永久兼容所有未来版本，使用前仍建议阅读版本说明和已知问题。

## 界面净化

### 隐藏视频提及区域中的游戏推广

部分带有游戏标签或相关内容的视频，会在详情页“视频提及”等区域展示额外的游戏推广卡片。启用该功能后，模块会在目标数据进入界面前进行识别和过滤，尽量保留正常的视频信息，同时隐藏对应推广内容。

该功能只针对已经识别的目标卡片，不会修改视频本身、播放器、评论区或账号数据。由于客户端不同版本可能采用不同的数据模型，模块同时保留了兼容入口和失败保护；未命中目标结构时会直接放行，而不是对未知对象进行强制修改。

### 隐藏 UP 主分享好物推广

视频详情页可能展示“UP 主分享好物”等商品推广内容。启用后，模块会隐藏已识别的商品推广区域，让简介、标签和其他详情信息保持更加简洁的排列。

此功能仅处理相应推广模块，不会屏蔽普通简介文字、视频标签、合集信息或评论内容。若客户端未来更换了推广卡片结构，功能可能暂时失效，但不应阻止视频详情页正常加载。

### 隐藏首页大卡轮播推荐

首页顶部或推荐流中可能出现占用较大展示空间的轮播卡片。该功能用于补全部分第三方环境下已经失效的首页大卡净化能力。

启用后，模块会尝试在轮播数据进入首页布局之前进行处理，减少大型卡片对首页浏览节奏的干扰。由于首页推荐结构经常随客户端版本变化，该功能的实际效果可能与哔哩哔哩版本、账号实验分组和地区配置有关。

### 隐藏暂停页广告

模块提供暂停页广告屏蔽能力，用于尝试处理视频暂停后出现的部分广告内容。该功能在[v1.0.7-alpha.3](https://github.com/jichuo1/Bilibili_Innocent_Lab/releases/tag/v1.0.7-alpha.3)与[v1.0.6](https://github.com/jichuo1/Bilibili_Innocent_Lab/releases#release-v1.0.6)前仍归类为实验性功能，在此之后转为正式功能并归类在“净化”下。效果可能受到客户端版本、账号实验分组、播放器类型和广告下发策略影响。

若开启后出现屏蔽行为异常、播放器控制层不完整或其他兼容问题，请先关闭该开关并重启哔哩哔哩。该功能不建议作为首次安装后的默认测试项目，应先确认基础净化和自由复制功能运行正常。

## 评论与简介自由复制

### 评论区自由复制

官方评论区的长按行为在不同版本中可能表现为复制全文、打开特定菜单，或者只能执行有限操作。模块提供了独立的评论自由复制能力：长按评论文本后，会在当前内容附近显示一个可选择文字的气泡，用户可以继续长按并拖动系统选择句柄，自由选择需要的文字片段，然后使用系统复制工具栏完成复制。

自由复制支持普通评论、较长评论、展开后的评论以及部分回复列表。模块会尽量读取评论数据中的完整原文，避免只复制折叠状态下屏幕上显示的截断内容。对于表情占位、换行和特殊文本结构，也会尽量保留可读形式。

评论区采用 RecyclerView 动态复用结构。为了避免快速滚动、展开回复和加载带图评论时产生明显卡顿，模块对绑定过程进行了专门调度：

- 滚动过程中只记录需要处理的评论，不集中执行全树绑定；
- 滑动停止后，在主线程空闲间隙分批完成处理；
- 优先处理最近进入当前视口的评论；
- 长按手势进行期间暂停批量操作，避免与气泡动画争用帧预算；
- 使用弱引用保存评论根节点，降低页面切换后的引用残留风险；
- 对图片、按钮和媒体点击容器保留宿主原有触摸行为。

带图评论的图片点击区域不会被自由复制监听器接管。用户长按正文并关闭复制气泡后，仍然可以正常点击评论图片进入预览。

### 视频简介自由复制

除评论区外，模块也支持长按视频详情页简介。触发后使用与评论区一致的自由复制气泡，用户可以选择简介中的部分文字，而不必复制整段内容。

简介在不同客户端版本中可能采用不同的可展开文本组件，因此模块使用运行时资源 ID 和通用触摸入口进行识别，并对多个已知版本的官方复制路径提供兼容处理。简介处于折叠状态时，模块会优先尝试读取完整原文，避免只获得界面上被省略的部分。

简介文本还会进行适度整理，包括：

- 统一不同形式的换行符；
- 清理尾部多余空白和空行；
- 处理部分由图标或 ReplacementSpan 产生的占位字符；
- 避免不可见占位内容在复制气泡中变成多余字母；
- 尽量保留正文原有段落结构；
- 在1.0.6版本中新增支持了对于原生文本中Emoji的无损映射展示，在剪贴板中哔哩哔哩自有Emoji将表现为文字形式。

### 气泡外观

自由复制气泡提供以下外观选项：

- 默认暗色气泡；
- 手动启用白底黑字的亮色模式；
- 自动跟随哔哩哔哩当前亮暗主题。

自动跟随开启后，模块会在进入视频详情页时判断一次当前主题，并缓存结果。弹出气泡时直接读取缓存，避免在长按瞬间执行额外反射操作。

气泡采用全屏透明 Dialog 承载，以保证 Android 系统文本选择句柄、浮动工具栏和复制操作能够正常工作。实际可见区域仍然只是定位在评论或简介附近的小型气泡。点击气泡外部会播放退出动画并关闭界面，点击气泡文字区域则可以继续选择文本。

## 漫游版本支持扩展

“漫游版本支持扩展”用于配合已经安装并启用的哔哩漫游模块工作。它不是哔哩漫游的替代品，也不提供账号、解析服务器、访问密钥或网络代理服务。

部分较新的哔哩哔哩客户端版本可能改变内部分析目标，使旧版漫游在读取或生成 Hook 信息时出现异常。启用扩展后，本模块会尝试修补已知的分析兼容问题，并协助漫游重新建立完整缓存，使其设置入口、页面定制和相关 Hook 能力能够在已适配的新版本中继续工作，同时缩短宿主冷启动时间。

当前实现包含以下兼容措施：

- 修补部分高版本客户端中的分析候选异常；
- 在缓存损坏、过期或版本变化时触发重新分析；
- 尽量避免无意义的重复全量分析和冷启动延迟；
- 在“我的”页面补充漫游设置入口；
- 通过跨进程 Provider、受权限保护的广播和本地缓存同步开关状态；
- 针对部分 MIUI/HyperOS 环境处理应用可见性与后台启动限制；
- 在功能关闭后恢复相应原生行为，避免模块状态长期残留。

开启该功能后，通常需要按照设置界面的提示重启哔哩哔哩两次，使缓存重建和后续快速启动路径依次完成，否则漫游部分功能可能不生效。不同哔哩漫游版本、LSPosed 分支和客户端版本之间可能存在差异，遇到问题时请同时提供三者的版本信息。

## 实验性功能

### 预见式返回动画

在支持预见式返回手势的 Android 系统中，可通过模块设置启用相应窗口能力，使返回手势能够展示系统提供的过渡预览。该功能主要面向 AOSP Android 14 及以上环境，部分厂商系统可能自行修改或关闭相关动画。

### 气泡亮暗色自动跟随

自动跟随会覆盖手动亮色气泡设置。用户在自动跟随开启时修改手动模式，模块会先显示确认提示，避免出现两个配色来源同时生效的情况。

## 自动版本适配

哔哩哔哩客户端更新后，混淆类名、方法名和参数签名都可能变化。为减少每次版本更新后都必须立即发布新模块的情况，项目加入了轻量级版本适配器。

适配器会结合类结构、字段类型、方法参数和 ViewBinding 特征定位部分关键 Hook 点，并将结果缓存到目标应用的本地缓存中。后续启动若版本未变化，会直接走缓存快路径，不重复扫描。

当检测到客户端版本变化、适配缓存不存在或用户主动清除缓存时，模块会重新执行适配。设置界面中的“重新适配当前版本”用于清除旧记录；确认后重启哔哩哔哩，模块将在下次启动时重新定位。

自动适配只能覆盖结构特征仍然相近的版本。如果客户端进行了大规模重构，模块可能只能保持部分功能，仍需等待项目更新。若升级客户端后出现功能失效，可依次尝试：

1. 打开模块设置；
2. 进入“实验性功能”；
3. 点击“重新适配当前版本”；
4. 确认清除缓存；
5. 重启哔哩哔哩；
6. 等待适配完成提示后再次进入对应页面测试。

## 模块设置与维护工具

### 激活状态

模块主页会显示当前是否已经被 Xposed/LSPosed 框架激活，并在可用时展示激活框架名称及 API 版本。如果一直显示“模块未激活”，请检查：

- LSPosed 是否正常运行；
- 模块是否已经启用；
- 作用域是否包含 `tv.danmaku.bili`；
- 修改作用域后是否已经强制结束并重新启动哔哩哔哩；
- 当前安装 APK 是否与 LSPosed 中启用的是同一个包。

### 隐藏桌面图标

用户可以隐藏模块的桌面启动图标。隐藏后仍可从 LSPosed 管理器的模块设置入口重新打开。

部分 LSPosed 版本带有“强制显示桌面图标”功能。如果隐藏操作没有生效，请先在 LSPosed 中关闭对应选项。

### 一键重启哔哩哔哩

设置界面提供“重启哔哩哔哩”入口，用于在修改功能后快速结束目标进程并重新启动应用。执行前会显示确认界面，减少误触。

如果设备未授予必要的 Root 能力、Shell 命令受限或厂商系统阻止后台拉起，重启操作可能失败。此时可以手动从最近任务中划掉哔哩哔哩，或在系统设置中强制停止后重新打开。

### 日志设置

模块日志可以独立开启或关闭，并提供两种详细度：

- **精简**：只输出显著错误、运行异常和关键失败信息；
- **完整**：输出 Hook 注册、功能命中和拦截详情，适合排查兼容问题。

日志通常可以在 LSPosed 管理器中查看。提交问题时，建议使用完整档复现一次，再导出与目标进程有关的日志。日志可能包含客户端版本、类名和运行状态，请在公开上传前自行检查并隐藏个人敏感信息。

### 更新检查

模块设置页支持 Stable 与 Preview 两种更新渠道，默认保持 Stable：Stable 只接收正式 Release；Preview 会同时比较正式版与 vX.Y.Z-alpha.N 预发布版，并选择语义版本最高的一项。切换渠道后会立即检查新渠道，Alpha 更新弹窗会显示明确的预发布风险提示。自动检查按渠道分别进行24小时低频节流，网络失败时不会持续弹窗干扰使用。发现新版本后，可以通过“版本详细”查看完整更新说明；GitHub API、详情页连接失败或超时时会按功能切换到对应镜像，也可以继续选择手动下载安装。

模块不会在后台静默安装更新。APK 安装、版本替换和是否使用测试版本始终由用户决定。

理论上几个已验证完毕的版本号的之间的客户端亦可使用，不保证功能完全实现，若您发现功能失效并希望项目进行适配，请按照README中提示的Issue流程进行操作。

## 安装方法

1. 从 [GitHub Releases](https://github.com/jichuo1/Bilibili_Innocent_Lab/releases) 下载 APK。
2. 在 Android 设备上安装或覆盖安装模块。
3. 打开 LSPosed 管理器。
4. 启用 `Bilibili Innocent Lab`。
5. 将官方哔哩哔哩 `tv.danmaku.bili` 加入模块作用域。
6. 强制停止哔哩哔哩，然后重新启动。
7. 打开模块设置，确认页面显示“模块已激活”。
8. 根据需要启用净化、自由复制或实验性功能。
9. 若设置未立即生效，使用模块内的“重启哔哩哔哩”，或手动强制停止目标应用。
10. 漫游版本支持扩展请按照页面提示完成两次重启。

覆盖安装模块后，一般不需要清除哔哩哔哩数据。除非发布说明明确要求，否则不要随意清空客户端数据、模块配置或漫游缓存。

## 推荐使用顺序

首次安装建议按以下顺序验证：

1. 确认模块已激活；
2. 只开启一个界面净化功能；
3. 重启哔哩哔哩并检查详情页或首页；
4. 测试评论区自由复制；
5. 测试视频简介自由复制；
6. 根据主题选择手动亮色气泡或自动跟随；
7. 确认基础功能稳定后，再尝试实验性功能；
8. 仅在已安装哔哩漫游且确有兼容需求时开启漫游扩展。

逐项启用更便于判断问题来源，也能避免多个模块同时修改同一页面时难以定位冲突。

## Release 通道

### Stable

稳定版用于日常使用。模块内置的更新检查默认只检查 GitHub 稳定 Release。稳定版会优先考虑已知功能、构建完整性和基础兼容性。

### Alpha

Alpha 版本用于提前验证新功能、适配新客户端或测试兼容性修复。它可能包含尚未完成广泛设备验证的改动，不建议在无法自行导出日志或恢复旧版本的设备上长期使用。

## 常见问题

### 模块显示未激活

确认 LSPosed 已启用模块，并检查作用域是否包含官方哔哩哔哩。修改作用域后需要重新启动目标应用，必要时重启设备。

### 开关已经打开，但功能没有生效

先强制停止并重新启动哔哩哔哩。若刚升级客户端，可以尝试“重新适配当前版本”。漫游扩展可能需要两次启动才能完成缓存重建。

### 评论长按没有出现自由复制气泡

检查评论自由复制开关是否开启，并确认当前页面属于已适配的官方评论区。若只有少量评论失效，请记录评论类型、是否带图、是否为回复列表以及客户端版本。

### 使用自由复制后图片无法打开

当前版本已经对带图评论的媒体容器进行专门保护。请确认安装的是最新构建，并彻底重启哔哩哔哩进程。如果仍能复现，请说明操作顺序以及气泡关闭后等待多久点击图片。

### 气泡内无法选择或复制文字

请确认没有其他模块同时 Hook 系统剪贴板、文本选择工具栏或 PopupWindow。部分厂商系统的文本选择组件经过深度定制，如遇崩溃请提供系统版本和 crash 日志。

### 首页轮播仍然出现

首页结构可能受到账号实验分组影响。请提供客户端版本、首页样式截图和完整日志，避免只使用“功能无效”作为问题描述。

### 漫游扩展开启后仍然异常

请同时提供：

- 哔哩哔哩版本；
- 哔哩漫游版本；
- 本模块版本；
- LSPosed 版本及分支；
- Android/ROM 版本；
- 是否完成两次重启；
- LSPosed 中目标主进程的相关日志。

### 与其他模块冲突怎么办

多个模块同时修改评论区、视频详情页、剪贴板、主题属性或漫游缓存时，可能发生执行顺序冲突。建议暂时关闭其他模块，只保留本模块复现；确认单模块正常后再逐个恢复。

## 性能与兼容设计

本模块包含多个运行在目标应用进程中的 Hook，因此在设计时尽量避免把复杂逻辑放入高频回调：

- 对滚动、触摸和文本绑定路径设置快速返回条件；
- 评论绑定使用空闲调度与分批处理；
- 反射获得的方法和字段会尽量缓存；
- 页面、Dialog 和评论 View 使用弱引用保存；
- 异步任务只持有 Application Context；
- 新版本适配结果写入缓存，避免每次启动重复扫描；
- 跨进程开关读取具有多级降级路径；
- 对自己的 Dialog、系统选择句柄和宿主媒体容器设置身份或来源豁免；
- 在 ROM 差异明显的窗口、状态栏和主题属性上使用显式配置。

项目不会为了追求“拦截更多内容”而无条件接管所有系统 API。对于 PopupWindow、Dialog、剪贴板、广播和触摸事件等影响范围较大的入口，优先根据对象身份、调用来源和手势生命周期判断是否属于模块目标，避免干扰图片预览、系统文本选择和宿主其他正常功能。
