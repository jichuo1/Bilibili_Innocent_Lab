## 项目简介

Bilibili Innocent Lab 是一个面向 Android 官方哔哩哔哩客户端的开源 Xposed / LSPosed 模块，支持 Root（LSPosed）和免 Root（NPatch / LSPatch 本地修补）两种方式加载。

它保留客户端原有的界面与操作习惯，重点解决广告推广多、推荐与评论杂音大、简介评论难以局部选取复制等问题，也提供视频插帧、音频处理、悬浮玻璃外观和免登录浏览等按需扩展功能。所有功能均有独立开关，绝大多数默认关闭，关闭后重启哔哩哔哩即恢复原状，配置支持本地备份与恢复。

### 能力总览

| 方向 | 代表功能 |
| --- | --- |
| 🧹 **净化** | 首页、动态、搜索、播放页与详情页的广告及多余卡片；开屏广告；竖屏视频流按类别过滤 |
| 🔎 **过滤** | 标题关键词、UP 主、标签、时长、播放量与发布时间；本地 AI 评论识别；可选自定义 API 语义过滤 |
| 📋 **自由复制** | 长按评论、视频简介或标题弹出气泡，自由拖选任意片段 |
| ▶️ **播放器** | 默认画质与编码、自定义倍速、缓冲策略、视频插帧（QCOM / RIFE 可选）、音频拯救、字幕样式、商单片段跳过 |
| 🎨 **外观** | 顶 / 底栏悬浮玻璃胶囊、自定义页面背景、卡片圆角与材质、开屏背景适配 |
| 🔒 **隐私** | 免登录浏览、无痕模式、清理分享链接追踪参数、小程序分享转为普通链接 |
| 🧰 **工具** | 回复脉络图、AI 视频总结与任务助手、配置备份还原、诊断与云控管理 |
| 📦 **免 Root** | 支持通过 NPatch / JingMatrix LSPatch 管理器以本地模式加载 |

> [!IMPORTANT]
> 下载、安装、编译、分发或使用本项目前，请完整阅读[声明与风险](#声明与风险)；不同意其中任何内容请勿使用。Xposed 模块可能随客户端更新失效，升级哔哩哔哩或遇到异常前建议先看 Release 说明。

## 快速开始

### 环境要求

| 项目 | 要求 |
| --- | --- |
| **Android 版本** | Android 8.1（API 27）及以上 |
| **运行环境** | 推荐 Root + LSPosed；也支持[免 Root 加载](#免-root-支持) |
| **目标应用** | 官方 Android 哔哩哔哩，包名 `tv.danmaku.bili` |
| **适配范围** | 已适配官方正式版 **8.84.0 ～ 9.20.0**；常见小版本升级可自动兼容，客户端大改版时部分功能可能需要等待模块更新 |
| **多开支持** | 仅支持包名仍为 `tv.danmaku.bili` 的系统多用户 / 应用双开 / 工作资料；改包名克隆或分身容器不支持，详见[多开与多用户](#多开与多用户) |
| **漫游扩展** | 需另行安装并启用兼容版本的哔哩漫游模块 |

### 安装与启用

| 步骤 | 操作 |
| :---: | --- |
| **1** | 从 [GitHub Releases](https://github.com/jichuo1/Bilibili_Innocent_Lab/releases) 下载并安装 APK（第三方仓库可能更新滞后）。覆盖安装无需清除数据，仅当更新说明明确提示时再清理相关缓存 |
| **2** | 打开 LSPosed 管理器，启用 `Bilibili Innocent Lab` |
| **3** | 在模块作用域中勾选官方哔哩哔哩（`tv.danmaku.bili`） |
| **4** | 强行停止并重新打开哔哩哔哩（若启动变慢或模块一直无法识别客户端，请检查并关闭 HMA-OSS 对哔哩哔哩的隐藏） |
| **5** | 打开模块设置主页，确认顶部显示「**模块已激活**」 |
| **6** | 按需开启净化、增强、美化或实验性功能开关；与“进阶设置”中同类的功能不要在多个模块重复开启 |
| **7** | 修改开关后点击模块内的「重启哔哩哔哩」，或手动强行停止客户端使其生效 |
| **8** | 配合哔哩漫游使用时，按页面引导检查缓存就绪后重启哔哩哔哩即可 |

### ROOT 权限说明

若设备已 Root，可酌情授予本模块 ROOT 权限，用于以下两项辅助操作：

- 修改设置后直接重启并确认哔哩哔哩生效；
- 读取诊断中心所需的部分本地排障状态。

模块不会将 ROOT 权限用于除此之外的用途，具体调用均可直接在源码中查阅核对。

### 推荐使用顺序

首次上手建议按下面的顺序逐项启用，方便分辨效果和排查问题：

1. 先确认模块主页已显示「模块已激活」；
2. 打开**一两个**常用净化开关，重启哔哩哔哩验证生效；
3. 试试评论、简介或标题长按自由复制，按深浅色喜好调整气泡外观；
4. 基础功能稳定后，再开启播放器插帧、音频处理、美观美化或 AI 类实验功能；
5. 确实需要兼容老版本哔哩漫游时，再启用漫游版本支持扩展。

## 免 Root 支持

未 Root 的设备可以通过补丁管理器本地修补官方哔哩哔哩加载本模块，目前支持 **NPatch** 与 **JingMatrix LSPatch** 的管理器（本地）模式：

| | **NPatch（Manager 模式）** | **JingMatrix LSPatch（本地 / Manager 模式）** |
| --- | --- | --- |
| **推荐版本** | NPatch Manager 1.0.7 及以上（Android 9+） | JingMatrix LSPatch 1.2（487）及以上 |
| **已测参考** | 哔哩哔哩 8.90.2，Android 16 / arm64 | 哔哩哔哩 9.13.0，Android 16 / arm64 |
| **内嵌（Embed）打包** | ❌ 当前暂不开放 | ❌ 当前暂不开放 |
| **模块内开关** | 同意条款后打开「免 Root 支持」 | 无需额外开启 NPatch 开关或通信兼容模式 |

> [!NOTE]
> 当前版本仅开放管理器本地修补模式，暂不支持直接把模块内嵌打进哔哩哔哩安装包（`--embed`）。

### 使用步骤

**NPatch 管理器模式**

1. 使用 NPatch 对官方哔哩哔哩进行 Manager 模式本地修补并安装；
2. 打开 NPatch 管理器，关联启用 `Bilibili Innocent Lab`；
3. 打开本模块设置 App，同意条款并在兼容设置中打开「**免 Root 支持**」，然后彻底重启哔哩哔哩。

**JingMatrix LSPatch 本地模式**

1. 在 LSPatch 管理器中选择「本地」模式修补官方哔哩哔哩，并关联 `Bilibili Innocent Lab`；
2. 安装修补后的哔哩哔哩，并保留本模块设置 App、打开完成条款授权；
3. 彻底关闭并重新启动哔哩哔哩，回到模块主页确认激活状态。

### 日常注意事项

- **保留模块设置 App**：免 Root 模式下，客户端需要通过模块设置 App 获取授权和配置；如果设置 App 被系统杀后台清理，请先打开一次设置 App，再冷启动哔哩哔哩。
- **改设置后手动重开**：增删功能开关后，需要手动强行停止并重新启动哔哩哔哩才能生效；若配置未能就绪，所有增强与净化功能会保持关闭，不会套用旧缓存。
- **升级与重装**：覆盖更新模块会保留现有设置；卸载重装则会清除条款记录与免 Root 授权，重装后需重新授权。个人开关偏好可通过「设置备份」导出与还原。

## 多开与多用户

模块仅对包名仍为 `tv.danmaku.bili` 的客户端生效：

| 多开方式 | 克隆后包名 | 是否支持 |
| --- | --- | :---: |
| 系统多用户 / 应用双开 / 工作资料 | 仍为 `tv.danmaku.bili` | ✅ 需在**该分身用户下**单独安装并启用一次 |
| 改包名多开工具 | 变为其他包名 | ❌ |
| VirtualApp 类分身容器 | 容器自身包名 | ❌ |

改包名或容器类多开即使注入代码，模块也无法正确匹配官方包名的资源与配置路径，因此不支持。

**在应用双开 / 多用户中启用的方法**（Xposed 服务按 Android 用户隔离分发）：

1. 在分身或目标用户空间里也安装一次 `Bilibili Innocent Lab`；
2. 在 LSPosed / 补丁管理器中切换到该用户，勾选启用模块并将哔哩哔哩加入作用域；
3. 在该用户下打开一次模块设置，让配置写入生效；
4. 强行停止并重启该用户下的哔哩哔哩。

排查提示可直接看模块首页：显示「当前用户下没有框架服务」通常说明第 2 步未在对应用户启用；显示「模块与哔哩哔哩位于不同用户」说明两者没有装在同一个用户空间里。

### 🏠 首页与导航

#### 顶栏与推荐流

| 功能 | 说明 |
| --- | --- |
| 隐藏首页游戏中心 | 移除首页顶部游戏中心图标 |

#### 视频插帧 `实验`

为最高 4K 分辨率的普通视频补充更顺滑的高帧率画面（如将 30 fps 补至 60 fps 档位），支持「自动选择」与「强制指定」两种控制策略，开启「插帧状态提示」可在开播时查看实际生效方式：

- **自动选择（默认）**：具备 QCOM 硬件运动估计能力的高通平台优先启用免下载模型的硬件补帧；其余 Vulkan GPU 或不支持硬件路径的视频会自动切到 RIFE v4.6 模型，并根据画质与性能预算自动调节档位。
- **强制指定插帧方式**：开启后可手动挑选「**插帧方式**」。选择窗口会自动探测本机 GPU 能力与支持的硬件/Vulkan 加速特性（如 Adreno / Mali·Immortalis / Xclipse·RDNA / PowerVR 及 FP16 / Subgroup / AHB 等）：
  - **设备支持高通硬件补帧时**：同时列出 `QCOM` 与 `RIFE` 供选择；
  - **设备不支持 QCOM 硬件路径时**：自动隐藏 `QCOM` 仅显示 `RIFE`，并在需要时提示一键下载 RIFE v4.6 模型；
  - 开启强制开关后，系统会锁定您选定的方案，**不会因为帧时间门槛自动切回或降级**。
- **边界与调节**：HDR 与受保护内容保持原版直通播放；支持自定义补帧帧率上限、开关状态提示及关闭温控降档（开启前需二次确认；高分辨率插帧会略增加耗电与画面延迟，音画始终保持同步）。

| 问题 | 排查方法 |
| --- | --- |
| 模块主页一直显示未激活 | 请核对：1）已在 LSPosed 中启用本模块；2）作用域包含官方哔哩哔哩 `tv.danmaku.bili`；3）强行停止并重新启动过哔哩哔哩（部分系统需要重启一次手机）。 |

## 面向开发者

本节面向希望二次开发、排查构建或了解底层实现机理的开发者。

<details>
<summary><b>构建与本地门禁</b></summary>

<br>

Gradle 工程位于仓库根目录下的 [`Bilibili_Innocent_Lab/`](Bilibili_Innocent_Lab) 子目录，弹幕线协议内核与视频插帧分别包含 Rust（`danmaku-wire`）及 C++/Vulkan 探测代码（`frame_window`）。

**常用命令（Windows PowerShell；Linux/macOS 将 `.\gradlew.bat` 替换为 `./gradlew`）**

```powershell
cd Bilibili_Innocent_Lab

# 反向查询受工作区改动影响的源码契约
.\gradlew.bat :app:contractsFor '-PinnocentLab.contractTarget=changed' --console=plain --no-daemon

# 运行完整本地验证门禁（Debug 编译 + JVM 单元测试与契约测试 + 完整 Lint + Release R8 混淆验证）
.\gradlew.bat assembleDebug testDebugUnitTest lintDebug minifyReleaseWithR8 --continue --console=plain --no-daemon
```

- **增量与快速检查**：日常迭代可用 `.\gradlew.bat :app:lintFast --console=plain --no-daemon`（与 `lintDebug` 共用同一套规则，仅分离报告输出目录到 `app/build/reports/lint/fast/`）；请始终使用 `--no-daemon` 并保留 Gradle 本地缓存，非插件签名或依赖变更不轻易 `clean`。
- **产物核验**：调试 APK 输出至 `Bilibili_Innocent_Lab/app/build/outputs/apk/debug/app-debug.apk`；部署测试后建议核对本地与设备上 `base.apk` 的 SHA-256。正式分发构建（Release/Embedded 打包签名）遵循仓库签名凭据与工作流隔离策略。

</details>

<details>
<summary><b>测试分层与源码契约</b></summary>

<br>

项目的 JVM 验证门禁共用 `testDebugUnitTest` 任务，在物理目录上明确拆分为两层：

| 层级 | 目录 | 作用与筛选参数 |
| --- | --- | --- |
| **行为测试（Unit）** | `app/src/test/java` | 验证协议编解码、规则过滤、配置目录快照、状态机与容错边界（`-PinnocentLab.testLayer=unit`） |
| **源码契约（Contract）** | `app/src/contractTest/java` | 借助严格锚点锁定宿主入口守卫、生命周期销毁、零分配热路径与外部依赖委托边界（`-PinnocentLab.testLayer=contract`） |

- 改动生产代码前可运行 `:app:contractsFor -PinnocentLab.contractTarget=<File.kt 或符号>` 快速定位关联契约；
- 源码契约基座 `SourceContract` 在 `after`/`before` 锚点缺失时直接失败，禁止退化为单参数回退；
- CI 验证流水线见 `.github/release-templates/run_gradle_gates.py`，会对 `unit` 与 `contract` 两层 JUnit XML 覆盖完整性以及 HTML Lint 有效错误数做硬门禁检查。

</details>

<details>
<summary><b>Hook 运行时与性能架构</b></summary>

<br>

- **框架与基础设施**：模块入口采用 Modern Xposed API（API 102），结合 Meguviz 家族依赖（`MeguvizRef`、`MeguvizUI`、`MeguvizAndroid`、`MeguvizMedia`）与 [Lumen Coacervation Engine](https://github.com/jichuo1/LumenCoacervationEngine) 视觉/动效库。
- **快路径与热路径约束**：Hook 回调、列表滚动、`RecyclerView`/`Compose` 绑定及触摸分发链路均采用预解析好的成员句柄，禁止触发全局 DEX 扫描、阻塞磁盘 I/O 或跨进程同步等待。
- **对象生命周期**：所有宿主 View、Activity、Dialog 与 Binding 均使用弱引用隔离或带明确销毁撤回；Protobuf/Moss 消息篡改严格按需 copy-on-change，不污染共享默认实例并保留未知字段。
- **异常隔离与免打扰**：挂入宿主线程、Handler 与主界面的异步/回调入口均包裹在 `HostThreadGuard` 中 fail-open 保底；针对 `PopupWindow`、长按手势与媒体预览容器设置了严格的对象归属与来源白名单。

</details>

<details>
<summary><b>版本自动重定位与免 Root 工具链</b></summary>

<br>

- **结构重定位与缓存**：针对客户端版本更新带来的混淆命名变化，版本适配器 `VersionAdapter` 按类特征、成员签名与辅助 DexKit 查询在后台完成定位并落盘带指纹校验的缓存；各功能家族按独立安装单元统计与诊断。
- **免 Root 配置通道与安全边界**：NPatch / LSPatch Manager 模式下的功能开关与条款授权均经过完整的版本、签名与条款校验才生效；免 Root 配置写入与回执校验互不越权，不会在未取得有效授权前放行旧缓存。
- **NPatch 本地修补工具与基线**：仓库内保留了免 Root 打包验证工具链，构建、修补及同证书升级细节见 [scripts/npatch/README.md](scripts/npatch/README.md)。

</details>
